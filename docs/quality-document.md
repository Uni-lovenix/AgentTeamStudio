# 质量文档

每个产品领域和架构层的质量快照。agent 和人都能通过这份文档快速了解项目哪里强、哪里弱。

**更新时机：** 每轮重要会话结束后，或开始新一阶段工作前。

**评级标准：**

- **A**：验证全部通过，架构干净，agent 能读懂，测试稳定
- **B**：验证通过，基本干净，可读性或测试覆盖有少量缺口
- **C**：部分可用，有已知缺口，部分代码 agent 不容易理解
- **D**：不可用，或存在重大结构问题

## 变更历史

### 2026-08-01 第五轮

- 变更内容：导出时在目标项目 `agents/` 目录下为每个智能体生成独立 Markdown 文件；`AGENTS.team.md` 增加智能体文件索引。
- 提升：每个智能体都有独立、可被 agent 直接读取的职责说明文件。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：所有智能体职责集中在单一 Markdown 文件中，不便于按角色读取

### 2026-08-01 第四轮

- 变更内容：团队配置改为写入 `AGENTS.team.md` 和 `agents.json`，不再覆盖 `AGENTS.md` / `CLAUDE.md`；当目标目录已有任一规则文件时，幂等追加“使用智能体规则在 AGENTS.team.md 文件”入口，两者都存在则都追加。
- 提升：导出不破坏既有 Codex/Claude 规则，同时仍能通过入口文件让 agent 读取团队配置。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：生成 `AGENTS.md` 可能覆盖用户原有 Codex 规则

### 2026-08-01 第三轮

- 变更内容：将团队生成从按技术栈/功能拆分改为按需求识别责任区块，并为每个角色赋予对应职责；同步更新 LLM 提示、测试、文档和 feature list。
- 提升：生成结果更符合“根据需求生成完成需求需要的角色”的产品目标，不再默认产出前端工程师、后端工程师等功能拆分角色。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：本地生成角色与需求关联不足

### 2026-08-01 第二轮

- 变更内容：修复 Electron sandbox preload 无法加载项目模块的问题，改用 esbuild 单文件打包 preload；修复发布包缺失 services/shared；新增 OpenAI/Anthropic 双协议 LLM 支持；补齐连接测试错误反馈。
- 提升：preload 桥接在 dev 和打包版均可加载；LLM 配置可连接 OpenAI 兼容与 MiniMax Anthropic 兼容接口。
- 下降：无
- 新发现的缺口：Windows 实际安装和 LLM 端到端验证仍需在 Windows/CI 环境执行
- 已关闭的缺口：新建项目无响应、测试连接无反馈、发布包启动缺模块

### 2026-08-01

- 变更内容：从空仓库实现 Agent Team Studio
- 提升：从占位文档升级为可编译、可测试的完整 Electron 应用
- 下降：无
- 新发现的缺口：真实 LLM 连接和 Windows 打包需要外部环境验证
- 已关闭的缺口：项目骨架、类型检查、单元测试、构建和导出路径
