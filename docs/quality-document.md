# 质量文档

每个产品领域和架构层的质量快照。agent 和人都能通过这份文档快速了解项目哪里强、哪里弱。

**更新时机：** 每轮重要会话结束后，或开始新一阶段工作前。

**评级标准：**

- **A**：验证全部通过，架构干净，agent 能读懂，测试稳定
- **B**：验证通过，基本干净，可读性或测试覆盖有少量缺口
- **C**：部分可用，有已知缺口，部分代码 agent 不容易理解
- **D**：不可用，或存在重大结构问题

## 变更历史

### 2026-08-03 RUP 过程管理

- 变更内容：生成团队全面引入轻量 RUP，统一将“冲刺协议”改称为“迭代协议”。`TeamConfig` 升到 schema v2 并新增 `processManagement`，包含启动、细化、构建、移交四阶段、里程碑、退出标准和迭代列表；旧 v1 草稿自动迁移。LLM 提示、团队预览、`AGENTS.team.md`、`agents.json`、规则文件追加入口和基准脚本同步支持 RUP 过程。Agent Team Studio 自身后续功能开发也使用 `docs/PROCESS.md` 中的 RUP 迭代管理。
- 提升：过程管理可编辑、可导出、可机器读取；责任区块直接映射到构建迭代；旧冲刺入口会自动迁移。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：生成团队只有冲刺协议，没有阶段、里程碑和结构化迭代过程

### 2026-08-02 冲刺协议协作流程

- 变更内容：生成团队固定包含“规划者”和“评估者”，需求责任区块生成一个或多个开发者角色；每项任务开始前由规划者制定冲刺协议，开发者按协议开发，评估者按协议校验并反馈给开发者修改。LLM 路径同样补齐必需角色和冲刺流程，导出到 `AGENTS.team.md`、`agents/*.md` 以及追加到 `AGENTS.md` / `CLAUDE.md` 的入口都会写入协作规则。
- 提升：所有生成结果具备统一的“规划 -> 冲刺协议 -> 开发 -> 评估反馈 -> 验收”闭环，开发者可以按需求责任区块扩展为多个。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：生成团队没有强制规划者、评估者和冲刺协议

### 2026-08-01 第六轮

- 变更内容：新增生成日志，界面展示“需求依据 -> 角色生成 -> 结果”的实际生成链路，而不是抽象步骤列表。
- 提升：生成过程对用户透明，能够看到具体信号和生成结果。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：用户无法理解角色生成的依据

### 2026-08-01 第五轮

- 变更内容：导出时在目标项目 `agents/` 目录下为每个智能体生成独立 Markdown 文件；`AGENTS.team.md` 改为智能体路由索引，移除重复的角色明细。
- 提升：每个智能体都有独立、可被 agent 直接读取的职责说明文件；`AGENTS.team.md` 与 `agents/*.md` 不再冗余。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：所有智能体职责集中在单一 Markdown 文件中，不便于按角色读取

### 2026-08-01 第四轮

- 变更内容：团队配置改为写入 `AGENTS.team.md` 和 `agents.json`，不再覆盖 `AGENTS.md` / `CLAUDE.md`；当目标目录已有任一规则文件时，幂等追加“使用智能体规则在 AGENTS.team.md 文件”入口，两者都存在则都追加。
- 提升：导出不破坏既有 Codex/Claude 规则，同时仍能通过入口文件让 agent 读取团队配置。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：生成 `AGENTS.md` 可能覆盖用户原有 Codex 规则

### 2026-08-01 第三轮

- 变更内容：将团队生成从按技术栈/功能拆分改为按需求识别责任区块，并为每个角色赋予对应职责；同步更新 LLM 提示、测试、文档和 feature list。
- 提升：生成结果更符合“根据需求生成完成需求需要的角色”的产品目标，不再默认产出前端工程师、后端工程师等功能拆分角色。
- 下降：无
- 新发现的缺口：无
- 已关闭的缺口：本地生成角色与需求关联不足

- 提升：preload 桥接在 dev 和打包版均可加载；LLM 配置可连接 OpenAI 兼容与 MiniMax Anthropic 兼容接口。
- 下降：无
- 新发现的缺口：Windows 实际安装和 LLM 端到端验证仍需在 Windows/CI 环境执行
