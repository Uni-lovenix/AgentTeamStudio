# RUP 过程管理

Agent Team Studio 自身后续功能开发采用轻量 RUP 过程。当前项目阶段为“构建”（Construction）；后续每个功能按一个构建迭代推进，迭代达到退出标准后再进入下一迭代或移交阶段。

## 阶段

| 阶段 | 目的 | 里程碑 | 当前状态 |
| --- | --- | --- | --- |
| 启动 | 确认功能价值、边界、约束和风险 | 生命周期目标 | 已完成 |
| 细化 | 降低技术风险，确定架构和迭代计划 | 生命周期架构 | 已完成 |
| 构建 | 按迭代完成功能实现、测试和评估闭环 | 初始可用能力 | 当前 |
| 移交 | 最终验收、文档交接和发布 | 产品发布 | 未开始 |

## 迭代协议

每个功能迭代开始前，在 `session-handoff.md` 记录：

- 迭代 ID 和名称
- 迭代目标
- 范围
- 实施计划
- 退出标准
- 验收证据

实现过程中仍遵守 Electron 分层、IPC 单一来源、结构化日志和原子写入约束。

## 不引入的部分

RUP 中不适合当前 agent 协作模型的部分会被省略：

- 不新增业务分析师、架构师、测试工程师、部署工程师或项目经理等独立 RUP 角色。
- 不维护企业架构、商业用例等重量级工件。
- 不做与 agent 执行能力无关的组织级变更管理流程。

保留的是：阶段与里程碑、迭代计划、风险驱动、评估反馈、阶段验收、文档交接和已知问题移交。

## 完成判定

一个迭代完成需要同时满足：

1. `npm run check` 通过。
2. `npm test` 通过。
3. `npm run build` 通过。
4. `bash scripts/benchmark.sh` 通过。
5. `bash scripts/cleanup-scanner.sh` 通过。
6. `feature_list.json` 中对应条目状态为 `pass`，并填写 `rupPhase` 与 `iteration`。
7. `docs/PRODUCT.md` 或 `docs/ARCHITECTURE.md` 已更新。
8. `session-handoff.md` 已记录本轮迭代结果。
